# 项目交付路线

## 项目定位

本项目是一个完整设备的固件工程，不是一组教学练习。

最终交付物是能够连接小智官方服务、完成录音、上传、接收和播放的 Arduino 工程。

正式代码由你亲手实现。我的职责是设计接口、提供参考实现、审查代码、定位问题，并维护项目文档。未经你明确要求，我不写入或修改代码文件。

固定条件：

- 开发板：ESP32-S3-DevKitC-1 N16R8
- 开发环境：Arduino IDE
- 服务端：小智官方服务
- 正式工程：`firmware/xiaozhi/xiaozhi.ino`

参考项目 `winwill2012/xiaozhi-ai-arduino` 只用于阅读模块拆分和部分驱动思路，不作为服务端方案。边界见 [06-参考项目与Arduino-IDE路线.md](06-参考项目与Arduino-IDE路线.md)。

## 集成顺序

为了避免音频、网络和硬件问题互相干扰，按下面顺序集成：

1. 工程骨架与板级配置
2. 状态显示与交互输入
3. 本地音频链路
4. 小智 OTA 与 WebSocket 协议
5. Opus 编解码与完整对话

这是实现顺序，不代表产品被拆成多个独立项目。所有代码最终都在同一个工程里。

## 交付里程碑

| 里程碑 | 进入条件 | 交付内容 | 验收标准 |
|---|---|---|---|
| M0 工程可用 | 环境安装完成 | `firmware/xiaozhi/` 可编译上传 | N16R8 参数正确，启动稳定 |
| M1 板级与交互 | M0 通过 | 按键、状态灯、LCD 显示模块 | 状态可见，长按不连发 |
| M2 本地音频 | M1 通过 | 麦克风采集、功放播放、缓冲链路 | 能采集、能播放、能回环 |
| M3 服务连接 | M2 通过 | WiFi、NTP、OTA、WebSocket | 能拿到会话并可重复重连 |
| M4 下行音频 | M3 通过 | Opus 解码、播放队列 | 能播放服务端语音 |
| M5 完整对话 | M4 通过 | Opus 编码、录音上传、状态机 | 能完成一轮以上真实对话 |

M2、M4 和 M5 是主要技术风险，优先保证接口清楚和验证手段可靠，再完善界面。

## 开始前的型号确认

接线前先确认模块类型，不能只看“录音模块”“功放模块”这种功能名称：

| 模块 | 需要确认 | 不符合时的处理 |
|---|---|---|
| 录音模块 | 是否为 INMP441、ICS-43434 等 I2S 数字麦克风 | 模拟麦克风需要重新设计输入方案 |
| 功放模块 | 是否为 MAX98357A 等 I2S 数字功放 | 模拟功放需要额外 DAC |
| LCD | 是否为 ST7789、240x240、SPI | 控制器、分辨率不同则修改初始化参数 |

确认后按 [硬件引脚参考.md](硬件引脚参考.md) 接线。

## M0：工程可用

**实现内容**

- Arduino IDE 和 ESP32 Core 3.3.12
- N16R8 板级参数
- 正式 sketch 目录和 `src/` 分层
- 版本号、配置和启动入口

**操作**

按 [01-环境搭建.md](01-环境搭建.md) 配好环境，并让正式工程通过编译。

**验收**

- 工程可以编译和上传
- 串口监视器工作在 115200
- 程序启动后稳定运行，不随机重启

## M1：板级与交互

**实现内容**

- `Config`：集中管理 GPIO 和运行参数
- `Button`：按键消抖和边沿检测
- `RgbLed`：板载状态灯
- `Display`：ST7789 状态显示

**验收**

- 按键按下和松开只各触发一次
- 运行时不使用阻塞式消抖
- 屏幕能显示设备状态

## M2：本地音频链路

**实现内容**

- `Microphone`：I2S 采集 16kHz PCM
- `Speaker`：I2S 播放 24kHz PCM
- `AudioPipeline`：缓冲、重采样和队列
- 独立音频任务与核心分配

**验收**

- 麦克风读数随说话变化
- 功放能播放测试音
- 回环链路无持续断音
- 音频循环中没有阻塞打印

参考 [04-I2S音频入门.md](04-I2S音频入门.md)。

## M3：服务连接

**实现内容**

- `Network`：WiFi、NTP、OTA 配置获取
- `Protocol`：小智 WebSocket 握手和文本消息
- 设备身份持久化和重连逻辑

**验收**

- OTA 能返回 WebSocket 配置
- WebSocket 能完成 hello 握手
- 能拿到 `session_id` 和音频参数
- 重连后流程可重复

细节见 [05-联网与协议.md](05-联网与协议.md)。

## M4：下行音频

**实现内容**

- Opus 解码模块
- 下行二进制帧处理
- 播放队列和状态切换

**验收**

- 能播放服务端返回的语音
- 播放期间不会被网络任务阻塞
- 播放结束能回到待机状态

## M5：完整对话

**实现内容**

- Opus 编码和 60ms 分帧
- 上行音频发送
- 待机、聆听、思考、播放状态机
- 超时、断线和错误恢复

**验收**

- 说“你好小智”后设备有反应
- 能连续完成多轮对话
- 断网后可恢复
- 屏幕状态和真实状态一致

## 调试方法

按二分法隔离问题：

- 音频没声音：先单独验证功放
- 功放正常：再验证麦克风采集
- 本地音频正常：再检查缓冲、协议和网络
- 网络正常但无声音：检查 Opus 帧格式和播放队列

每次联调记录版本、测试条件、现象和结论，后续排查依赖同一套固定条件。

## 参考项目的使用时机

按已实现的模块有选择地阅读参考项目：

1. M1 后：参考 `Application`、`GlobalState` 的模块组装方式
2. M1 后：参考 `LvglDisplay` 和 `src/ui/` 的显示层拆分
3. M2 后：参考 `RecordingManager`、`AudioPlayer` 的 I2S 和队列
4. M3 后：以 `78/xiaozhi-esp32` 的 `main/ota.cc` 和 `main/protocols/` 为准
5. Opus 阶段：以官方 `audio_service` 和实际可编译库为准
