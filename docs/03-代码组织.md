# 工程代码组织

目标：在正式工程里把按键和灯封装成类，学会多文件工程。

## 为什么需要这一步

后面会有音频、网络、显示、状态机。如果全塞在一个 `.ino` 里，很快就没人看得懂，包括你自己。

算法题写单个文件是常态，但工程代码要把"一个模块一个文件"当成习惯。

## Arduino IDE 的多文件规则

Arduino IDE 有个特殊规定：**sketch 主文件所在的文件夹名，必须和主文件同名**。

正式工程会逐渐长成：

```
firmware/xiaozhi/
├── xiaozhi.ino      主文件
├── Config.h         引脚和常量
├── Version.h        工程版本
├── Button.h
├── Button.cpp
├── Led.h
└── Led.cpp
```

把其他 `.h` / `.cpp` 放在 `.ino` 同级目录即可，IDE 会自动编译。**子目录里的文件不会被自动编译**，先别用子目录。

`Button` 和 `Led` 是正式工程里的第一批模块。后续 `Display`、`Microphone`、`Speaker`、`Network` 也按同样方式加入。

## 头文件怎么写

头文件里放声明，用 `#pragma once` 防止重复包含（比传统的 include guard 简洁）。

`Led.h`：

```cpp
#pragma once
#include <Arduino.h>

class Led {
public:
  Led(uint8_t pin);
  void begin();
  void set(bool on);
  void toggle();
  bool isOn() const;

private:
  uint8_t pin_;
  bool on_ = false;
};
```

## 实现文件怎么写

`Led.cpp`：

```cpp
#include "Led.h"

Led::Led(uint8_t pin) : pin_(pin) {}

void Led::begin() {
  pinMode(pin_, OUTPUT);
  set(false);
}

void Led::set(bool on) {
  on_ = on;
  digitalWrite(pin_, on_ ? HIGH : LOW);
}

void Led::toggle() {
  set(!on_);
}

bool Led::isOn() const {
  return on_;
}
```

注意构造函数后面的 `: pin_(pin)` 是**初始化列表**，比在函数体里赋值更规范，对类成员也更快。

## 按键类

按键要处理抖动和边沿，逻辑比灯复杂，正好用类包起来。

`Button.h`：

```cpp
#pragma once
#include <Arduino.h>

class Button {
public:
  explicit Button(uint8_t pin, uint32_t debounceMs = 30);
  void begin();
  // 返回 true 表示"这一帧检测到一次按下"
  bool pressed();

private:
  uint8_t pin_;
  uint32_t debounceMs_;
  bool lastRaw_ = false;
  uint32_t lastChangeMs_ = 0;
};
```

`Button.cpp`：

```cpp
#include "Button.h"

Button::Button(uint8_t pin, uint32_t debounceMs)
    : pin_(pin), debounceMs_(debounceMs) {}

void Button::begin() {
  pinMode(pin_, INPUT_PULLUP);
  lastRaw_ = (digitalRead(pin_) == LOW);
}

bool Button::pressed() {
  bool raw = (digitalRead(pin_) == LOW);
  uint32_t now = millis();
  bool triggered = false;

  if (raw != lastRaw_ && (now - lastChangeMs_) > debounceMs_) {
    lastChangeMs_ = now;
    lastRaw_ = raw;
    if (raw) {
      triggered = true;   // 只在按下那一刻返回 true
    }
  }
  return triggered;
}
```

`explicit` 关键字防止编译器把整数隐式转成 Button 对象，是个好习惯。

## 主文件

把 `xiaozhi.ino` 临时改成下面的结构，然后继续向前演进：

```cpp
#include "Led.h"
#include "Button.h"
#include "Config.h"

Led led(config::kRgbLedPin);
Button button(config::kBootButtonPin);

void setup() {
  Serial.begin(115200);
  delay(1000);
  led.begin();
  button.begin();
  Serial.println("ready");
}

void loop() {
  if (button.pressed()) {
    led.toggle();
    Serial.print("led = ");
    Serial.println(led.isOn() ? "on" : "off");
  }
}
```

主文件只负责组装，不写具体硬件实现。不要新建 `blink_button` 项目，所有正式模块都直接加入 `firmware/xiaozhi/`。

## 验收标准

- [ ] 目录里有 5 个文件（1 个 `.ino` + 2 组 `.h/.cpp`）
- [ ] 编译通过，原有按键行为不变
- [ ] 主文件里读不到 `digitalRead` / `digitalWrite`，全被类包住了

## 面向对象的三个原则（现在就够用）

1. **封装**：数据和行为放在一起，外面看不到内部细节
2. **单一职责**：一个类只干一件事。别写一个 `AudioAndWifiManager`
3. **初始化分离**：构造函数只管存参数，`begin()` 才碰硬件

第 3 条特别重要。全局对象在 `setup()` 之前就被构造了，那时硬件还没初始化，在构造函数里直接操作 GPIO 会出问题。
