# 小智 Arduino 实现项目

在 ESP32-S3 面包板上实现一个能连接小智官方服务、完成真实语音对话的设备。

## 项目目标

最终交付一个可持续维护的 Arduino 固件项目，而不是教程示例或互不相干的练习。

交付标准：

- 设备启动后连接 WiFi 和小智服务
- 按键后开始录音
- 麦克风 PCM 数据按小智协议编码、分帧并上传
- 接收服务端音频并解码播放
- LCD 显示网络、录音、思考和播放状态
- 断线、超时和错误能够恢复

## 固定技术边界

| 项目 | 固定方案 |
|---|---|
| 服务端 | 小智服务 |
| 设备接入方式 | OTA 获取配置，再连接返回的 WebSocket 地址 |
| 音频协议 | 小智 Opus 音频帧和小智 WebSocket 协议 |
| 第三方密钥 | 不在设备代码中使用豆包、Coze 或其他服务密钥 |
| 服务地址 | 不把 WebSocket 地址永久写死，以 OTA 返回结果为准 |
| 开发环境 | Arduino IDE |
| 开发板 | ESP32-S3-DevKitC-1 N16R8 |

参考项目 `winwill2012/xiaozhi-ai-arduino` 的自建服务链路只用于阅读，不作为本项目的服务端方案。协议细节以 `78/xiaozhi-esp32` 和 [05-联网与协议.md](docs/05-联网与协议.md) 为准。

## 项目性质与分工

这是一个完整产品项目，不是以讲解基础知识为目标的课程。

正式代码由你亲手实现；我负责：

- 设计模块边界和接口
- 给出可供参照的实现思路和代码
- 检查你写的代码
- 定位编译错误、协议问题和硬件问题
- 维护项目文档和目录结构

默认不写入或修改 `.ino`、`.h`、`.cpp` 等代码文件。只有你明确说“写入工程”“计入”“按这个修改文件”时，我才会落盘。正式代码以你的实现为准。

## 硬件

- ESP32-S3-DevKitC-1 N16R8 开发板（面包板）
- 1.54 寸 ST7789 彩屏 240x240
- 录音模块（确认为 INMP441 类 I2S 数字麦克风后再接线）
- 功放模块（确认为 MAX98357A 类 I2S 数字功放后再接线）+ 小喇叭

引脚定义见 [硬件引脚参考.md](docs/硬件引脚参考.md)。

模块型号确认方法见 [06-参考项目与Arduino-IDE路线.md](docs/06-参考项目与Arduino-IDE路线.md)。

## 使用建议

1. 始终迭代 `firmware/xiaozhi/xiaozhi.ino`，它才是正式工程。
2. 按交付路线推进，每个模块通过验收后再接入下一层。
3. 参考代码只用于验证接口和硬件事实现；正式代码由你自己写。
4. 遇到问题先查避坑清单，再针对最小模块排查。

## 开发者基础

你已有的基础完全够用：C++ 语法、算法思维、位运算、复杂度直觉。

开发环境固定为 Arduino IDE。`winwill2012/xiaozhi-ai-arduino` 是 PlatformIO 项目，也只参考它的模块拆解和硬件驱动思路，不把它的服务端协议和密钥方案搬进来。具体边界见 [06-参考项目与Arduino-IDE路线.md](docs/06-参考项目与Arduino-IDE路线.md)。

需要新建立的习惯只有三条：

- 程序永不结束，`loop()` 一直循环
- 串口打印是主要的调试手段
- 时间是共享资源，`delay()` 会害死音频
